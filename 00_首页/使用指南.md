# 使用指南

## 信息放在哪里

- **角色自身事实**：放在角色目录的专题页。
- **跨角色事实**：建立关系、事件或组织笔记，再从双方页面链接。
- **未确认设定**：使用 `canon: tentative`，不要混入已确认事实。
- **废弃设定**：使用 `canon: discarded` 或移入 `99_归档`。
- **修订历史**：依靠 Git；只有对创作有意义的版本节点才写入变更日志。

## 命名规则

- 笔记使用自然名称：`涟.md`、`生物研究所.md`。
- 角色内部专题使用序号保持顺序：`01_基础信息.md`。
- 委托单：`COM-年份-序号-角色-画师.md`。
- 稿件：`日期-角色-画师-类型-v01.ext`；未知信息可暂用“未记录”。

## Properties 约定

- `type`：`character`、`character_setting`、`world`、`organization`、`location`、`event`、`relationship`、`commission`、`artwork`、`source_reference`。
- `status`：`idea`、`draft`、`developing`、`stable`、`deprecated`。
- `canon`：`canon`、`tentative`、`alternate`、`discarded`。
- 实体之间使用 Obsidian 双向链接；标签只用于 `oc/character` 等宽泛分类。

## 推荐工作流

1. 从模板新建角色、关系、委托或稿件笔记。
2. 在正文第一次出现实体时建立链接。
3. 通过 Bases 查看状态，不重复维护手写清单。
4. 每次较大修改后查看 Git diff，再提交一个语义清晰的版本。
5. 图片量明显增加后再考虑 Git LFS；当前规模无需引入。

## 发布到公开档案

公开站 `lian-archive` 是本资料库的生成投影，当前只发布纯文本核心设定。默认情况下所有笔记均为私有；需要公开的整篇笔记必须显式填写：

```yaml
publish: true
archive_path: lian/basic-info
archive_section: 角色 / 涟
archive_order: 10
archive_summary: 涟的姓名、种族、年龄、体型与世界归属
mood: calm
```

- `archive_path` 是稳定公开 URL，不应随本地目录移动而改变。
- `archive_section` 与 `archive_order` 控制公开列表的分组和顺序。
- 标记为公开意味着正文整体可以公开；价格、联系方式和委托沟通等内容不要混入公开笔记。
- 暂不公开的局部段落可放在 `<!-- archive:omit:start -->` 与 `<!-- archive:omit:end -->` 之间。
- 当前阶段不发布图片；素材必须在授权与署名信息齐全后，才进入后续媒体发布流程。
